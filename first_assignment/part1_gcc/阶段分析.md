## 三、源程序

源程序为：

```text
first_assignment/part1_gcc/fib.c
```

程序读取整数 `n`，先输出 `a=0` 和 `b=1`，然后按照给定循环计算并输出斐波那契数列。

输入输出使用 SysY 运行时库函数：

- `getint`
- `putint`
- `putch`

C 程序中直接声明了这三个函数，不包含 `sylib.h`。这样可以避免 `sylib.h` 中的全局缓存变量与本项目运行库发生重复定义，同时保持与 SysY 运行库的链接接口。

程序包含以下语言结构：

- 整数变量声明；
- 赋值语句；
- 函数调用；
- 算术运算；
- 关系运算；
- `while` 循环；
- `return` 语句。

## 六、编译器内部阶段

### 6.1 词法分析

编译器读取 `fib.i`，将其切分为标识符、关键字、整数常量、运算符、分隔符和行标记。

本程序涉及的主要记号包括：

- 标识符：`main`、`a`、`b`、`i`、`n`、`t`、`getint`、`putint`、`putch`；
- 关键字：`int`、`while`、`return`；
- 常量：`0`、`1`、`10`；
- 运算符：`=`、`+`、`<`；
- 分隔符：`(`、`)`、`{`、`}`、`;`。

### 6.2 语法分析

语法分析器根据 C 语法规则构造语法树，识别：

- 函数定义；
- 变量声明；
- 赋值语句；
- 函数调用语句；
- `while` 语句；
- `return` 语句。

Tree dump 文件：

```text
artifacts/fib.c.original
```

该文件表明 GCC 已识别 `main` 函数及其内部语句结构。例如，`while` 循环在内部树中被表示为标签和条件跳转。

### 6.3 语义分析

语义分析阶段检查并确定：

- 所有变量均为有符号 32 位 `int`；
- `n`、`a`、`b`、`i`、`t` 的声明和作用域；
- `getint` 的返回值赋给 `n`；
- `putint` 接收一个整型实参；
- `putch` 接收换行符的 ASCII 值 `10`；
- 循环条件和算术表达式的类型；
- `main` 的返回值为 `int`。

### 6.4 GIMPLE 中间表示

GIMPLE dump 文件：

```text
artifacts/fib.c.gimple
```

核心结构为：

```text
n = getint ();
a = 0;
b = 1;
i = 1;
putint (a);
putch (10);
putint (b);
putch (10);
goto <loop_condition>;

<loop_body>:
t = b;
b = a + b;
putint (b);
putch (10);
a = t;
i = i + 1;

<loop_condition>:
if (i < n) goto <loop_body>; else goto <loop_exit>;
```

GIMPLE 使用临时的三地址形式表达控制流，循环被转换成标签、条件跳转和无条件跳转。

### 6.5 RTL 中间表示

RTL dump 文件：

```text
artifacts/fib.c.rtl-expand
artifacts/fib.c.rtl-final
```

RTL 已体现 RISC-V 后端特点：

- 函数参数和返回值使用寄存器；
- 普通整型变量在 `-O0` 下主要保存在栈中；
- 函数调用表示为 `call_insn`；
- 条件比较表示为 `jump_insn`；
- 32 位整型加法对应 RISC-V 的 `addw`；
- 比较前需要将 32 位整数符号扩展到 64 位寄存器。

`rtl-expand` 是 RTL 展开后的初始结果，`rtl-final` 是经过后端优化和寄存器分配后的最终 RTL。

## 七、RISC-V 汇编阶段

`-O0` 汇编文件：

```text
artifacts/fib.s
```

函数主体摘录：

```text
addi    sp,sp,-48
sd      ra,40(sp)
sd      s0,32(sp)
addi    s0,sp,48

call    getint
mv      a5,a0
sw      a5,-32(s0)

sw      zero,-20(s0)
li      a5,1
sw      a5,-24(s0)

lw      a5,-20(s0)
mv      a0,a5
call    putint

li      a0,10
call    putch

addw    a5,a4,a5
addiw   a5,a5,1
blt     a4,a5,.L3
```

### 7.1 栈帧和调用约定

1. 使用 `addi sp,sp,-48` 分配 48 字节栈帧。
2. 保存返回地址 `ra` 和帧指针 `s0`。
3. 函数实参放入 `a0` 至 `a7`，返回值放入 `a0`。
4. 调用 `getint` 后，返回值从 `a0` 保存到局部变量 `n`。
5. 调用 `putint` 前，将待输出值放入 `a0`。
6. 返回时恢复 `ra` 和 `s0`，调整 `sp` 后执行 `jr ra`。

### 7.2 常见指令与语义

| 指令 | 作用 |
| --- | --- |
| `addi sp,sp,-48` | 扩展栈帧 |
| `sd` | 保存 64 位寄存器 |
| `sw` | 写入 32 位整数 |
| `lw` | 读取 32 位整数 |
| `li` | 装入立即数 |
| `mv` | 寄存器之间传送数据 |
| `addw` | 32 位整数加法 |
| `addiw` | 32 位整数加立即数 |
| `sext.w` | 将 32 位结果符号扩展为 64 位 |
| `blt` | 有符号小于时跳转 |
| `call` | 调用函数 |
| `jr ra` | 返回调用者 |

### 7.3 循环映射

循环条件：

```c
while (i < n)
```

对应的关键流程为：

1. 从栈中读取 `i` 和 `n`；
2. 使用 `sext.w` 将 32 位值符号扩展为 64 位；
3. 使用 `blt` 比较 `i` 是否小于 `n`；
4. 条件成立时跳转到循环体；
5. 循环体结束后跳回条件判断。

### 7.4 函数调用映射

```text
call getint
call putint
call putch
```

说明编译器只生成外部函数调用，不生成运行库函数的具体实现。函数符号将在链接阶段由 `libsysy_riscv.a` 解析。

## 八、`-O0` 与 `-O2` 对比

| 文件 | 行数 | 字节数 | 主要特征 |
| --- | ---: | ---: | --- |
| `artifacts/fib.s` | 349 | 4837 | 变量频繁存取栈，便于观察 |
| `artifacts/fib.O2.s` | 53 | 787 | 变量放入寄存器，控制流被简化 |

`-O2` 后的主要变化：

1. 汇编文件从 349 行减少到 53 行。
2. `a`、`b`、`i` 等局部变量尽量保存在寄存器中。
3. 循环条件由 `blt` 改写为观察值更直接的 `ble` 和 `bne`。
4. 使用更多 callee-saved 寄存器 `s0` 至 `s3`。
5. 增加了寄存器保存和恢复代码，但循环体明显缩短。
6. 外部函数调用仍然保留，因为 `putint` 和 `putch` 具有可观察的副作用，不能随意删除。

该对比说明优化阶段不仅改变机器指令数量，也会影响寄存器分配和栈帧组织，但必须保持原程序可观察行为不变。

## 九、与预处理和汇编的对应关系

以变量初始化为例：

```c
a = 0;
b = 1;
i = 1;
```

在 `-O0` 汇编中表现为：

```text
sw zero,-20(s0)
li a5,1
sw a5,-24(s0)
li a5,1
sw a5,-28(s0)
```

可见：

- 常量 `0` 可以使用 `zero` 寄存器；
- 常量 `1` 先装入临时寄存器，再写入栈；
- 变量访问在 `-O0` 下通常需要一次 `lw` 或 `sw`。

这说明源程序、中间表示和最终汇编之间的语义保持一致，但表达形式随阶段逐步接近目标机器。

## 十、结论

1. `riscv64-unknown-elf-gcc` 能够直接完成从 C 源文件到 RISC-V 汇编的处理。
2. 预处理阶段负责头文件展开和宏处理，仍处于源语言级别。
3. Tree、GIMPLE 和 RTL 展示了编译器内部逐步降低抽象层次的过程。
4. 最终生成的 `.s` 文件包含标准 RISC-V 栈帧、寄存器使用、函数调用和条件跳转。
5. `-O2` 能明显减少栈访问和汇编规模，但不会删除具有输入输出副作用的调用。
6. 本阶段产物为下一步的汇编和链接提供输入，具体交接命令见 `交接文档.md`。
