## 六、RISC-V 实现与 LLVM IR 的差异说明

两种实现语义相同，但表达层次不同。

需要特别修正此前的一个表述：

- LLVM IR 中的 `icmp` 只是逻辑比较，不是 RISC-V 硬件比较指令；
- LLVM RISC-V 后端在处理 64 位寄存器中的 32 位有符号比较时，同样需要先进行符号扩展；
- 手写汇编也需要使用 `sext.w` 后再执行 `blt/bgt` 等分支；
- 因此 `sext.w` 是 RV64 对 32 位整数语义的实现要求，不是“LLVM IR 与手写汇编之间的本质区别”。

手写汇编中的主要映射关系：

| SysY/C 操作 | RISC-V 实现 |
| --- | --- |
| 32 位加法 | `addw` |
| 32 位减法 | `subw` |
| 32 位乘法 | `mulw` |
| 32 位除法 | `divw` |
| 32 位取余 | `remw` |
| 32 位有符号比较前 | `sext.w` |
| 函数调用 | `call` |
| 返回 | `ret` |

## 七、栈帧和 ABI

`main` 的栈帧处理：

1. `sp` 下压 64 字节；
2. 保存 `ra` 和使用的 `s1` 至 `s6`；
3. 栈指针保持 16 字节对齐；
4. 函数调用前将参数放入 `a0/a1`；
5. 返回值从 `a0` 读取；
6. 返回前恢复 callee-saved 寄存器并调整 `sp`。

`gcd` 和 `is_even` 为叶函数，不需要栈帧。

## 九、修正后的 MLIR 层次说明

正确的逻辑层次为：

```text
Torch / Triton / Linalg / Tensor
  -> HFusion
  -> HIVM
  -> lower-level HIVM
```

各层职责：

- **HFusion**：基于 Linalg 扩展，处理硬件相对无关的结构化计算、类型合法化、算子融合和 AutoSchedule。
- **HIVM**：面向昇腾硬件，表达 Tile 级计算、GM/UB 搬运、流水同步、CV 核映射和片上内存规划。
- **HACC**：表达 Host/Device 函数属性和异构建模。
- **Annotation / Scope**：提供编译器提示和作用域结构。
- **Linalg**：上游 MLIR 方言，不应与 HIVM 写成同一个方言层级。
- **LLVM dialect / LLVM IR**：下游表示，属于后续 hivmc/LLVM 后端链路。

本任务只需要观察中端方言转换和 lowering，不需要真实 NPU。
